# 风格库 · Style Library

> 这是一个**持续收集**的设计风格配方库。每当我（或你）研究出一种新的页面设计风格，
> 就把它的「可复刻配方」记录在这里。下次要做新旅行攻略时，你只要说「用 XX 风格做」，
> 我读对应配方就能精确还原，不用每次重新研究、也不用凭记忆乱猜。

## 这个文件夹解决什么问题

之前做平潭攻略时发现：HTML 风格容易「单一」，原因是配色/字体/装饰物都靠临场发挥。
本库把每种风格**固化为配方**——配色 token、字体栈、签名元素、CSS 片段、页面骨架、反模式，
全部写死。复刻时只换内容、不换语言。

## 文件结构

```
风格库/
├── README.md           ← 你在这里
├── 风格索引.md         ← 一页速查：所有风格 + 按场景选风格
├── _新增风格模板.md    ← 加新风格时，复制此模板填写
├── 01-瑞士国际主义.md  ← 单风格配方（含可直接复制的 CSS）
├── 02-炫光霓虹.md

├── 04-电影纸感.md
├── 05-和纸柔光.md
└── 06-复古海报.md
```

## 怎么用（给你）

1. **选风格**：打开 [风格索引.md](./风格索引.md)，按「适合场景」或心情挑一种，或直接报编号/名字。
2. **下指令**：例如「用 04 电影纸感做一份 2027 春天京都攻略」。
3. **我读配方 → 开工**：我会读对应配方文件，按配色/字体/签名元素/骨架生成新页面。
   内容层（行程/清单/花销/照片/日记）默认沿用既有 `assets/data.js + app.js` 交互架构，
   保证可编辑、可上传图片、数据跨页共享。

## 怎么新增风格（给我自己 / 未来会话的我）

当你丢给我一个新风格 skill 仓库或参考样例时：

1. 研究它，提炼出「辨识度最高的那一种」风格（一个仓库可能含多套，挑最有代表性的一套）。
2. 复制 [_新增风格模板.md](./_新增风格模板.md)，填满每一节。**配色必须给 `:root` CSS 变量**，
   签名元素必须给**可直接复制的 CSS 片段**，不能只写形容词。
3. 文件名 `NN-风格名.md`（NN 为下一个编号）。
4. 回填 [风格索引.md](./风格索引.md)：在总表加一行、在「按场景选」补一条。
5. 若同时产出了示例 HTML，在配方末尾「示例」节登记路径。

## 配方必须包含什么（验收标准）

一份合格配方，让一个**完全没有上下文的新会话**也能 1:1 复刻：

- [ ] **配色**：`:root` 变量（底色/墨色/强调/辅助/线色），注明哪个是「单一锚点」
- [ ] **字体**：字体栈（含中文 fallback）、标题/正文/铬件三档分工、字号策略
- [ ] **全局纪律**：圆角？阴影？玻璃？动效限制？写清楚允许/禁止
- [ ] **签名元素**：3-5 个「看到它就知道是这个风格」的元素，附 CSS
- [ ] **页面骨架**：旅行页的标准章节顺序 + 每节用什么版式
- [ ] **组件配方**：导航/hero/章节标题/chip/待办/时间线/卡片/花销/照片/页脚 的具体写法
- [ ] **反模式**：哪些常见做法会破坏这个风格（防止复刻走样）
- [ ] **字体加载**：是否依赖 CDN、断网 fallback
